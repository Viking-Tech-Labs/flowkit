## Session conventions

Managed by the `session-discipline` plugin from flowkit. Each rule ends with what it replaces, so I can judge it; I delete the ones I do not want. `/session-discipline:adopt update` rewrites everything between the two marker comments and shows the difference first, so rules of my own go outside the markers.

- **Close every stop.** Lead with the answer in two or three plain sentences, written for someone who has not read the session. A turn that finishes work ends with four blocks: `DONE` (one line per item, and per repository: branch, committed or not, pushed or not, how it was verified), `FOR ME` (numbered; only the steps that need my hands, such as a device, a web console, a secret or an approval), `OPEN` (what is blocked, and on what), `LEFT` (what remains of the task, or "nothing left"). If nothing needs me, say so. *Replaces: reading back through the session to learn what state things are in.*
- **Finish what you can.** Split the work into what you can do now and what needs me, complete the first part fully, and list the second under `FOR ME`. *Replaces: instructions handed to me for steps you could have run yourself.*
- **Minimal diff.** Keep the code the way it was and change only what the task needs: no restructuring, no extra parameters, no commented-out or dead code, no comments that narrate the obvious. If a bigger refactor looks right, say so in one line and leave it. *Replaces: reviewing a rewrite I did not ask for.*
- **Commit on green, never push unasked.** When validation passes, commit in the repository's own style without asking. Push, open a pull request or merge only when I say so. Never switch branches or stash over uncommitted work you did not make. *Replaces: typing "commit it" after every change, and pushes I did not expect.*
- **Reviews against the acceptance criteria.** A review checks the change against what the story or ticket asked for, not only against the code. Findings are a stable numbered list, each with a verdict on whether it is worth fixing, so "fix 1 to 3" is a complete instruction. Possible simplifications come after the findings and do not count as findings. After fixes: validate, commit. *Replaces: reviews that polish style and miss an unmet requirement.*
- **Runbook answers.** When I ask how to do something by hand, answer with a numbered list of commands I can paste: each one checked, no `<PLACEHOLDER>`, no missing step, no path you have not confirmed exists. If a value is mine to fill in, say which one and where it comes from. *Replaces: commands that fail on the first paste.*
- **Secrets.** Read credentials from the environment or the system keychain and never print them. Check that one is present without showing it (`${VAR:+set}`), and redact tool output that echoes one. If I paste a secret by accident, tell me so I can rotate it. *Replaces: tokens sitting in a transcript.*
- **Subagents for exploration.** Broad searches, test runs and log reading go to a subagent that returns a conclusion in a few lines, never a dump; do not re-read what you delegated. Everything else runs in this session: no fan-out of agents unless the task spans repositories or I ask for it. *Replaces: a context full of file listings, and a panel of agents for a one-file change.*
- **Decision interview.** When you need something from me that is expensive to reverse, or that different readings would turn into different work, neither ask a bare question nor assume: follow the `decision-interview` skill (investigate first, every question with a recommended answer, asked as choices I can pick). Routine judgment calls you make yourself and state as an assumption at the end. *Replaces: "what do you want here?" and silent assumptions.*
